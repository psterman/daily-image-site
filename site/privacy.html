过目 Lookon（Chrome 扩展）隐私政策

适用产品：过目 Lookon —— Chrome 应用商店上的 Chrome 扩展（Manifest V3）
最近更新：2026-11-22
扩展版本：0.10.0

本政策适用于过目 Lookon 这个 Chrome 扩展。它与「过目站」（my.onetone.app）和「一声 OneTone」桌面端
是不同产品：桌面端的隐私政策见 www.onetone.app/privacy。

一句话

过目是一个侧栏 AI 阅读扩展：你打开侧栏，它读你当前正在看的那一个页面的正文，送到你自己选定的模型通道做总结/解读，回复显示在侧栏里。

扩展没有自建服务器，不向开发者发送任何数据。 你打开侧栏时，页面正文只会发往你启用的那一个模型通道（Kimi / WorkBuddy / 小浣熊 / OpenCode Zen / Kilo 公共 / Pollinations 公共），或者完全不联网（Chrome 本机 AI）。

1. 扩展会读取什么

数据 具体内容 什么时候读
当前页正文 当前活动标签页的可见文本（document.body.innerText）、页面标题、页面 URL 见下方第 2 节
登录凭据 OAuth 的 access token / refresh token、短信登录得到的会话凭据 你点击「连接/登录」时
你的偏好 提示词模板、所选通道与模型、剪藏内容 你在设置里改的时候
模型回复 通道返回的文本 每次请求后

扩展不收集：浏览历史、书签、Cookie、密码表单内容、键盘输入、剪贴板、地理位置、身份信息、设备指纹、任何广告或统计标识。

2. 什么时候会读当前页

只有在你主动打开侧栏之后才会发生。侧栏关闭时，扩展不读任何页面。

侧栏打开期间：

  1. 每 4 秒刷新一次「当前活动标签页」的标题与正文，用来感知你切了页面或页面内容变了。
  2. 自动「页面解读」在以下时机触发：切换标签页、当前页加载完成、或你手动点侧栏上的快捷芯片。
    • 同一「标签页 + 同一 URL + 同一内容指纹」只跑一次，不会反复发。
    • 页面正文过短、或没有启用任何通道时，不会触发。
  3. 手动动作：点「总结 / 要点 / 通俗讲 / 译成中文」或在输入框追问。
  4. 右键菜单「用过目总结此页」「加入过目（本页摘要）」「加入过目（仅链接）」。
  5. 过目阅读器站内「AI 阅读」：由过目站页面指定要读的 URL，扩展打开一个隐藏标签页读取该页正文，结果回传给页面。
  6. 剪藏同步：你点右键菜单把当前页加入过目时，扩展先把它存在本机；等你在已登录的过目站打开时，再交给该页面。

一个重要的前提

在你没有启用任何模型通道之前，扩展只在本机读取正文，用来判断"要不要自动解读"，不会把任何内容发到网络。只有当你点了某个通道的「一键启用」或完成登录之后，页面正文才会发往那个通道。

3. 数据去了哪里

扩展只与你选定的通道通信。以下是全部出站目标：

通道 出站主机 说明
Kilo 公共通道 https://ai-gateway.kilo.ai 第三方免 API Key 公共服务
Pollinations 公共通道 https://text.pollinations.ai 第三方免 API Key 公共服务
Kimi 网页会员 https://www.kimi.com、https://kimi.moonshot.cn 你用 Kimi 账号登录后的会员对话
WorkBuddy（腾讯 CodeBuddy） https://copilot.tencent.com 你完成 CodeBuddy 登录后
小浣熊（商汤） https://xiaohuanxiong.com 微信扫码登录后
OpenCode Zen https://opencode.ai、https://console.opencode.ai 设备登录授权后
Chrome 本机 AI 无网络请求 Gemini Nano 完全在本机运行

扩展不发送数据的地方

  • 不发送给你（开发者）。扩展没有统计、没有埋点、没有遥测、没有崩溃上报、没有后端。
  • 不主动向 my.onetone.app（过目站）发起任何请求。扩展与过目阅读器之间只通过页面内的 postMessage 通信。
  • 有一处需要说清楚：剪藏（clip）。你点右键菜单「加入过目」时，扩展会把标题、链接和（如果你选的）本页摘要先存在本机扩展存储里，工具栏图标上会出现一个待同步角标。当你在已登录过目账号的状态下打开过目站时，扩展才会把这些剪藏内容交给该页面；过目站随后怎么处理、是否上传到它自己的服务器，适用过目站自己的隐私政策，与本扩展无关。扩展本身不会替你把内容传到任何地方。
  • 不会把 A 页的内容发到 B 页。剪藏只存在本机扩展存储里（上限 40 条）。

一个需要单独说明的技术细节

启用 WorkBuddy 通道时，扩展会用 Chrome 的 declarativeNetRequest API，仅对 copilot.tencent.com 这一个域名，把请求的 User-Agent 头改成一个标识为 CodeBuddy CLI 的字符串，以便复用该服务的官方接口。这条规则不影响其他任何网站，也不涉及其他请求头。

4. 数据存在哪、多久

  • 全部在本机，存在 Chrome 扩展存储（chrome.storage.local）里：登录 token、偏好设置、剪藏内容。
  • 只有少量非敏感偏好（比如提示词模板、界面设置）会同步到你的 Chrome 账号（chrome.storage.sync）。token 和剪藏内容不会同步。
  • 扩展不写 Cookie，不写浏览历史。
  • 卸载扩展 = 全部删除。 卸载后本机存储的 token 与剪藏一并清除；Chrome 账号里同步过的那几条偏好需要你手动在 chrome://extensions 的「同步」开关里关掉。

5. 第三方通道

当你启用某个通道时，页面正文会经过那个通道的服务器，并适用它自己的隐私政策与用户协议：

  • Kilo 公共通道、Pollinations 公共通道 是第三方提供的免费公共通道，不是过目（也不是 Kimi）提供的服务。它们是免 API Key 的公共服务，稳定性、可用性与数据处理方式由第三方决定。
  • Kimi / WorkBuddy / 小浣熊 / OpenCode Zen 的通道调用的是各自官方服务的接口，你使用它们需要遵守各自的服务条款。
  • 你随时可以在侧栏里断开某个通道（点通道上的关闭按钮）。

如果你不希望任何内容离开本机，只用「Chrome 本机 AI」通道即可 —— 那条通道完全离线。

6. 权限说明

权限 用途
https://*/* 读取你当前正在看的网页正文用于总结 —— 这是扩展的核心功能
tabs 读当前活动标签的 URL（浏览器受限页面无法读到 URL）
scripting 把读取正文的脚本注入当前页
storage 在本机保存 token、偏好与剪藏
sidePanel 在 Chrome 右侧栏显示扩展界面
activeTab 你点击工具栏图标时，临时访问当前页
contextMenus 提供「用过目总结此页」右键菜单
declarativeNetRequestWithHostAccess 仅用于 WorkBuddy 通道的单域名 User-Agent 规则
指定域名 Kimi、过目站、以及上表列出的各模型通道主机 —— 扩展只会访问这些域名

7. 你的控制权

  • 关闭侧栏 → 立即停止读取页面。
  • 断开通道 → 侧栏里点通道上的关闭按钮；之后正文不会再发往该通道。
  • 关掉自动解读 → 在侧栏设置里关掉「打开侧栏时自动页面解读」。
  • 清数据 → chrome://extensions → 过目 → 「详细信息」→ 清除扩展数据。
  • 卸载 → 彻底移除扩展与本机存储的全部内容。

8. 儿童

过目是通用型效率工具，不面向 13 岁以下儿童。

9. 政策变更

政策如有实质变更（例如新增通道、改变数据流向），会随扩展版本更新同步更新本页日期，并在扩展的更新说明里注明。
